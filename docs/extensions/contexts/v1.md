---
title: Contexts extension v1
description: Optional PACT extension for reading a conversation's message history.
---

**URI:** `https://openpactprotocol.org/extensions/contexts/v1`

An optional [A2A extension](https://a2a-protocol.org/latest/topics/extensions/)
that lets a personal agent read the messages of a past conversation with a
Brand, including replies a human agent sent after `message:send` returned. It
builds on PACT Identity ([spec §2–§4](../../spec.md#2-transport)) and
changes nothing there. A Provider that doesn't advertise it is fully
conformant.

The key words MUST, MUST NOT, SHOULD and MAY are to be interpreted as described
in [RFC 2119](https://www.rfc-editor.org/rfc/rfc2119). Timestamps are
[RFC 3339](https://www.rfc-editor.org/rfc/rfc3339) strings in UTC.

<a name="1-declaration"></a>

## 1 · Declaration

A Brand that supports the extension lists it in its card's
`capabilities.extensions`:

```json
{
  "capabilities": {
    "streaming": false,
    "pushNotifications": false,
    "extendedAgentCard": false,
    "extensions": [
      {
        "uri": "https://openpactprotocol.org/extensions/contexts/v1",
        "description": "Conversation message history.",
        "required": false
      }
    ]
  }
}
```

- `required` MUST be `false`. Personal agents that ignore the extension keep
  working.
- Personal agents MAY send `A2A-Extensions: https://openpactprotocol.org/extensions/contexts/v1`.
  Providers serve the route and metadata below whether or not it is sent.
- On a Brand whose card doesn't list it, the route below gets `404`
  ([spec §2.2](../../spec.md#22-operations)).

<a name="2-list-messages"></a>

## 2 · List messages

One route, relative to the interface URL. It takes the personal-agent JWT
([spec §3.2](../../spec.md#32-personal-agent-jwt)) and fails like any other route
([spec §3.4](../../spec.md#34-failure)). Successful responses use
`Content-Type: application/a2a+json`.

```http
GET {interfaceUrl}/contexts/f0c12e6b-231e-4d92-a610-2518a0f27d20/messages?pageSize=50
Authorization: Bearer <pa-jwt>
A2A-Version: 1.0
```

```json
{
  "messages": [
    {
      "messageId": "m-001",
      "contextId": "f0c12e6b-231e-4d92-a610-2518a0f27d20",
      "role": "ROLE_USER",
      "parts": [{ "text": "I need help with my order." }],
      "metadata": {
        "https://openpactprotocol.org/extensions/contexts/v1": {
          "createdAt": "2026-09-30T12:00:00Z"
        }
      }
    },
    {
      "messageId": "r-001",
      "contextId": "f0c12e6b-231e-4d92-a610-2518a0f27d20",
      "role": "ROLE_AGENT",
      "parts": [{ "text": "Sure, what is the order number?" }],
      "metadata": {
        "https://openpactprotocol.org/extensions/contexts/v1": {
          "createdAt": "2026-09-30T12:00:02Z",
          "author": "ai"
        }
      }
    }
  ],
  "nextPageToken": "",
  "pageSize": 50
}
```

Each entry is an A2A `Message`. Oldest message first. Default `pageSize` 50.

<a name="21-pagination"></a>

### 2.1 Pagination

As A2A `ListTasks`:

- `pageSize` is an integer from 1 to 100. The response repeats the size used.
- `pageToken` is opaque. Send back a `nextPageToken` unchanged to get the next
  page.
- `nextPageToken` is always present. `""` means this is the last page.
- A bad `pageSize` or `pageToken` gets `INVALID_PARAMS`.

<a name="22-access"></a>

### 2.2 Access

A caller sees only conversations with this Brand, from this personal agent,
for this `sub`: the same owner that [spec §4.2](../../spec.md#42-context) binds
a `contextId` to. An unknown `contextId` and one owned by someone else both get
`INVALID_PARAMS`, without saying which.

<a name="3-message-metadata"></a>

## 3 · Message metadata

Each message from §2 carries an object under the extension URI in `metadata`:

| Field       | Type                | Present on              |
| ----------- | ------------------- | ----------------------- |
| `createdAt` | timestamp           | Every message.          |
| `author`    | `"ai"` or `"human"` | Every `ROLE_AGENT` one. |

Personal agents MUST ignore fields they don't know.

<a name="4-security"></a>

## 4 · Security

| Layer       | Rule                                                                              |
| ----------- | --------------------------------------------------------------------------------- |
| Who gets in | §2 needs the personal-agent JWT, verified as for `message:send`.                  |
| Scoping     | One Brand per interface URL; one `(personal agent, sub)` per conversation (§2.2). |
| Ownership   | Unknown and foreign `contextId`s are indistinguishable (§2.2).                    |

<a name="5-conformance"></a>

## 5 · Conformance

A Provider that advertises the extension implements §2–§3 for that Brand. The
conformance suite (`e2e/contexts.test.ts`) checks them when the card lists the
extension and skips otherwise.
