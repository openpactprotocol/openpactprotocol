---
title: Contexts extension v1
description: Optional PACT extension for conversation history and personal-agent platform callbacks.
---

**URI:** `https://openpactprotocol.org/extensions/contexts/v1`

An optional [A2A extension](https://a2a-protocol.org/latest/topics/extensions/)
that lets a personal agent read its past conversations with a Brand and receive
replies that arrive after `message:send` has returned, for example from a human
agent. It builds on PACT Identity ([spec §2–§4](../../spec.md#2-transport)) and
changes nothing there. A Provider that doesn't advertise it is fully
conformant.

The key words MUST, MUST NOT, SHOULD and MAY are to be interpreted as described
in [RFC 2119](https://www.rfc-editor.org/rfc/rfc2119). Timestamps are
[RFC 3339](https://www.rfc-editor.org/rfc/rfc3339) strings in UTC.

<a name="1-declaration"></a>

## 1 · Declaration

A Brand that supports the extension lists it in its card's
`capabilities.extensions`:

```json
{
  "capabilities": {
    "streaming": false,
    "pushNotifications": false,
    "extendedAgentCard": false,
    "extensions": [
      {
        "uri": "https://openpactprotocol.org/extensions/contexts/v1",
        "description": "Conversation history and platform callbacks.",
        "required": false
      }
    ]
  }
}
```

- `required` MUST be `false`. Personal agents that ignore the extension keep
  working.
- Personal agents MAY send `A2A-Extensions: https://openpactprotocol.org/extensions/contexts/v1`.
  Providers serve the routes and metadata below whether or not it is sent.
- On a Brand whose card doesn't list it, the routes below get `404`
  ([spec §2.2](../../spec.md#22-operations)).

<a name="2-conversation-history"></a>

## 2 · Conversation history

Two routes, relative to the interface URL. Both take the personal-agent JWT
([spec §3.2](../../spec.md#32-personal-agent-jwt)) and fail like any other route
([spec §3.4](../../spec.md#34-failure)). Successful responses use
`Content-Type: application/a2a+json`.

| Method | Path                            | Result                                        |
| ------ | ------------------------------- | --------------------------------------------- |
| `GET`  | `contexts`                      | `200` `{ contexts, nextPageToken, pageSize }` |
| `GET`  | `contexts/{contextId}/messages` | `200` `{ messages, nextPageToken, pageSize }` |

<a name="21-list-contexts"></a>

### 2.1 List contexts

```http
GET {interfaceUrl}/contexts?pageSize=20
Authorization: Bearer <pa-jwt>
A2A-Version: 1.0
```

```json
{
  "contexts": [
    {
      "contextId": "f0c12e6b-231e-4d92-a610-2518a0f27d20",
      "status": "escalated",
      "createdAt": "2026-09-30T12:00:00Z",
      "lastMessageAt": "2026-09-30T12:04:10Z"
    }
  ],
  "nextPageToken": "",
  "pageSize": 20
}
```

| Field           | Rule                                                        |
| --------------- | ----------------------------------------------------------- |
| `contextId`     | The `contextId` from [spec §4.2](../../spec.md#42-context). |
| `status`        | `open`, `escalated` (a human handles it), or `closed`.      |
| `createdAt`     | When the conversation started.                              |
| `lastMessageAt` | Optional. When its latest message was stored.               |

Newest conversation first. Default `pageSize` 20.

<a name="22-list-messages"></a>

### 2.2 List messages

```http
GET {interfaceUrl}/contexts/f0c12e6b-231e-4d92-a610-2518a0f27d20/messages?pageSize=50
Authorization: Bearer <pa-jwt>
A2A-Version: 1.0
```

```json
{
  "messages": [
    {
      "messageId": "m-001",
      "contextId": "f0c12e6b-231e-4d92-a610-2518a0f27d20",
      "role": "ROLE_USER",
      "parts": [{ "text": "I need help with my order." }],
      "metadata": {
        "https://openpactprotocol.org/extensions/contexts/v1": {
          "createdAt": "2026-09-30T12:00:00Z"
        }
      }
    },
    {
      "messageId": "r-001",
      "contextId": "f0c12e6b-231e-4d92-a610-2518a0f27d20",
      "role": "ROLE_AGENT",
      "parts": [{ "text": "Sure, what is the order number?" }],
      "metadata": {
        "https://openpactprotocol.org/extensions/contexts/v1": {
          "createdAt": "2026-09-30T12:00:02Z",
          "author": "ai"
        }
      }
    }
  ],
  "nextPageToken": "",
  "pageSize": 50
}
```

Each entry is an A2A `Message`. Oldest message first. Default `pageSize` 50.

<a name="23-pagination"></a>

### 2.3 Pagination

As A2A `ListTasks`:

- `pageSize` is an integer from 1 to 100. The response repeats the size used.
- `pageToken` is opaque. Send back a `nextPageToken` unchanged to get the next
  page.
- `nextPageToken` is always present. `""` means this is the last page.
- A bad `pageSize` or `pageToken` gets `INVALID_PARAMS`.

<a name="24-access"></a>

### 2.4 Access

A caller sees only conversations with this Brand, from this personal agent,
for this `sub`: the same owner that [spec §4.2](../../spec.md#42-context) binds
a `contextId` to. `GET contexts` omits everyone else's. On
`contexts/{contextId}/messages`, an unknown `contextId` and one owned by
someone else both get `INVALID_PARAMS`, without saying which.

<a name="3-message-metadata"></a>

## 3 · Message metadata

Messages carry an object under the extension URI in `metadata`:

| Field       | Type                | Present on                                              |
| ----------- | ------------------- | ------------------------------------------------------- |
| `createdAt` | timestamp           | Every message from §2.2 or §4.                          |
| `author`    | `"ai"` or `"human"` | Every `ROLE_AGENT` message from §2.2 or §4.             |
| `status`    | a context `status`  | Every `message:send` reply. The status after this turn. |

Any field MAY also appear where the table doesn't require it. Personal agents
MUST ignore fields they don't know.

<a name="31-human-handoff"></a>

### 3.1 Human handoff

- When the Brand hands a conversation to a human, its status becomes
  `escalated`. Escalated conversations accept `message:send` as usual.
- If a message reaches a human who doesn't answer at once, the reply is an
  acknowledgement: a `ROLE_AGENT` message with `status` in its metadata. A2A
  requires at least one part, so it MUST have one. It SHOULD be a short text
  part, such as `"A team member will reply here."`.
- The human's answer arrives later: in §2.2 and, if configured, as a §4
  callback.
- A `closed` conversation follows [spec §4.2](../../spec.md#42-context):
  `message:send` to it gets `UNSUPPORTED_OPERATION`.

<a name="4-callbacks"></a>

## 4 · Callbacks

A Provider MAY push conversation events to a personal-agent platform. These
are platform-level callbacks, not A2A push notifications; cards keep
`pushNotifications: false`.

<a name="41-configuration"></a>

### 4.1 Configuration

The personal agent and the Provider agree out of band, once per personal
agent (not per Brand or User), on an HTTPS callback URL and a shared secret.
PACT defines no registration endpoint.

<a name="42-events"></a>

### 4.2 Events

The Provider `POST`s one JSON object per event. A new message:

```json
{
  "contextId": "f0c12e6b-231e-4d92-a610-2518a0f27d20",
  "message": {
    "messageId": "r-007",
    "contextId": "f0c12e6b-231e-4d92-a610-2518a0f27d20",
    "role": "ROLE_AGENT",
    "parts": [{ "text": "I've issued the refund; it posts in 3–5 days." }],
    "metadata": {
      "https://openpactprotocol.org/extensions/contexts/v1": {
        "createdAt": "2026-09-30T12:20:00Z",
        "author": "human"
      }
    }
  }
}
```

A status change:

```json
{ "contextId": "f0c12e6b-231e-4d92-a610-2518a0f27d20", "status": "closed" }
```

The body names only the `contextId`. The personal agent maps it to the User
and Brand it started that conversation for.

<a name="43-signature"></a>

### 4.3 Signature

```http
POST {callbackUrl}
Content-Type: application/json
X-A2A-Signature: sha256=3f1c…
```

The value after `sha256=` is the lowercase hex HMAC-SHA256 of the raw request
body bytes, keyed with the shared secret. The personal agent MUST verify it
over the bytes it received, before parsing, with a constant-time comparison,
and reject a mismatch.

<a name="44-delivery"></a>

### 4.4 Delivery

- A `2xx` response acknowledges the event.
- The Provider MAY retry after a network failure or a `5xx`. It SHOULD treat
  any `4xx` as final.
- Events can repeat or be lost. Personal agents SHOULD drop repeats by
  `messageId` and use §2 to recover missed events.

<a name="5-security"></a>

## 5 · Security

| Layer       | Rule                                                                              |
| ----------- | --------------------------------------------------------------------------------- |
| Who gets in | §2 routes need the personal-agent JWT, verified as for `message:send`.            |
| Scoping     | One Brand per interface URL; one `(personal agent, sub)` per conversation (§2.4). |
| Ownership   | Unknown and foreign `contextId`s are indistinguishable (§2.4).                    |
| Tampering   | Callbacks are HMAC-signed over the raw body (§4.3) and sent over HTTPS.           |
| Leaks       | Callback bodies carry no User or Brand id beyond the `contextId`.                 |

The signature covers the body only, with no timestamp, so a captured callback
can be replayed. Dropping repeats by `messageId` (§4.4) limits the effect.
Rotate the shared secret out of band.

<a name="6-conformance"></a>

## 6 · Conformance

A Provider that advertises the extension implements §2–§4 for that Brand;
§4 only for personal agents that configured a callback. The conformance suite
(`e2e/contexts.test.ts`) checks §1–§3.1 when the card lists the extension and
skips otherwise.
